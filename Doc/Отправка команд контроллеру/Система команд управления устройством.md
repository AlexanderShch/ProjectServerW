# Система команд управления устройством

## Актуальный порядок работы

В рабочем режиме сервер инициирует обмен. Команда сервера имеет формат [Type][Code][DataLen][Data][CRC16], ответ контроллера — [AA 55][Type][Code][Status][DataLen][Data][CRC16]. CRC Modbus вычисляется без AA 55 и передаётся младшим байтом вперёд. Длина поля DataLen относится только к Data.

При запуске STM32 сервер запрашивает версию и группы параметров 5, 6 и 7, затем устанавливает интервал. Запрос группы 7 ограничен общим бюджетом 950 мс. После запуска сервер периодически отправляет SEND_STATE (03/08) с байтом 01. Ответ 03/08 содержит 60 байт базовой телеметрии и байт флагов. Бит 0 (смещение 60 в Data) означает, что есть события. Старый запрос без параметров получает 60 байт. Для получения флага отдельной команды нет.

Сервер отвечает на телеметрию DATA_OK или DATA_FALSE (00/01 или 00/02). В авторежиме после DATA_OK контроллер отправляет лог регулирования 00/01 с 113 байтами данных. Сервер также читает прежние варианты лога с 89, 105 и 109 байтами. Повтор неизменившейся телеметрии с ошибочной CRC сервер подтверждает DATA_OK и отбрасывает.

В RAM контроллера 16 мест общей очереди. Диагностика занимает до 12 мест, четыре места доступны кнопкам даже при заполнении диагностикой. Записываются обработанные физические СТАРТ и СТОП, первый отказ активного датчика в серии и восстановление. Переполнения считаются раздельно для кнопок и диагностики. Перезагрузка очищает очередь.

По флагу сервер читает головную запись командой GET_EVENT (03/0D) и записывает её в log.txt. После принудительной записи файла сервер отправляет ACK_EVENT (03/0E), и контроллер удаляет выданную запись. Повтор не создаёт дубликата строки благодаря идентификатору загрузки и номеру события. При наличии следующих событий сервер продолжает чтение. Флаг служебный и в WorkData не экспортируется.

GET_EVENT принимает 16-байтовый кандидат идентификатора сессии. Ответ содержит идентификатор (16 байт), потери кнопок (4), потери диагностики (4), количество записей (1). При непустой очереди идут номер (4), секунды от запуска (4) и тип (1). Типы 1 и 2 — СТАРТ и СТОП, типы 3 и 4 — сбой и восстановление. Длина данных ответа — 25, 34 или 61 байт. ACK_EVENT принимает идентификатор (16) и номер (4). Многобайтовые поля имеют порядок little-endian.

Дополнение для датчика занимает 27 байт. Первые восемь однобайтовых полей содержат индекс, адрес, функцию, причину, ожидаемую и принятую длину, код UART и длину снимка. Далее идут время ответа в мс (2 байта), число неудачных попыток и длительность серии в секундах (по 4), затем снимок кадра (9 байт, значащие байты указаны длиной снимка).

Коды причины 0–7 обозначают отсутствие ответа, поздний ответ, незавершённый кадр, ошибку UART, короткий кадр, ошибку CRC, ошибку формата и прочий сбой обмена. Коды 8–13 обозначают чужой адрес, неверную функцию, неверный ByteCount, лишние байты, исключение Modbus и неверное эхо записи. Код 255 соответствует успешному ответу при восстановлении.

Для прошивок без байта флагов сервер использует прежнее чтение кнопок GET_BUTTON_EVENTS (03/0B) с интервалом не менее 30 с и подтверждение ACK_BUTTON_EVENTS (03/0C). После INVALID_CODE опрос возобновляется при новом подключении или обнаружении перезапуска.


Документ описывает фактическую систему команд в `ProjectServerW` (по состоянию текущего кода `Commands.h/.cpp` и `DataForm/CommandsDefroster`).

## Формат кадра команды (сервер -> контроллер)

```
[Type][Code][DataLen][Data...][CRC16]
 1 байт 1 байт  1 байт  0..N      2 байта
```

- CRC16 считается по всем байтам кадра, кроме последних 2 байт CRC.
- Формирование кадра: `BuildCommandBuffer(...)`.
- Максимальный размер буфера: `MAX_COMMAND_SIZE = 96`.

## Типы команд

| Тип | Код | Назначение |
|---|---:|---|
| `TELEMETRY` | `0x00` | Подтверждение телеметрии (`DATA_OK`, `DATA_FALSE`) |
| `PROG_CONTROL` | `0x01` | Управление процессом (START/STOP/RESET...) |
| `CONFIGURATION` | `0x02` | Настройка параметров |
| `REQUEST` | `0x03` | Запрос данных/состояния |
| `DEVICE_CONTROL` | `0x04` | Управление устройствами (зарезервировано протоколом) |

## Коды команд

### TELEMETRY (`Type=0x00`)

| Команда | Код | Назначение |
|---|---:|---|
| `DATA_OK` | `0x01` | Телеметрия принята |
| `DATA_FALSE` | `0x02` | Телеметрия отклонена (например CRC) |

### PROG_CONTROL (`Type=0x01`)

| Команда | Код |
|---|---:|
| `START` | `0x01` |
| `STOP` | `0x02` |
| `PAUSE` | `0x03` |
| `RESUME` | `0x04` |
| `RESET` | `0x05` |

### CONFIGURATION (`Type=0x02`)

| Команда | Код | Комментарий |
|---|---:|---|
| `SET_TEMPERATURE` | `0x01` | Установка температуры |
| `SET_INTERVAL` | `0x02` | Интервал измерений (`uint16`) |
| `SET_MODE` | `0x03` | Режим |
| `SET_DEFROST_PARAM` | `0x04` | Один параметр дефроста |
| `SET_DEFROST_GROUP` | `0x05` | Пакет параметров группы (5/6) |
| `LOAD_DEFROST_DEFAULTS` | `0x06` | Заводские параметры дефростации (без payload); прошивка ≥ 2.7.0 |

### REQUEST (`Type=0x03`)

| Команда | Код | Комментарий |
|---|---:|---|
| `GET_VERSION` | `0x02` | Версия прошивки |
| `GET_CMD_INFO` | `0x04` | Аудит последней команды |
| `GET_DEFROST_PARAM` | `0x06` | Один параметр дефроста |
| `GET_DEFROST_GROUP` | `0x07` | Пакет параметров группы |
| `SEND_STATE` | `0x08` | Запрос текущего состояния |
| `GET_ALARM_FLAGS` | `0x09` | Регистры аварий устройств/датчиков |
| `GET_SENSOR_DIAG` | `0x0A` | Сводка UART5 за период, 85 байт данных |
| `GET_BUTTON_EVENTS` | `0x0B` | Чтение только кнопок для совместимости |
| `ACK_BUTTON_EVENTS` | `0x0C` | Подтверждение записей кнопок для совместимости |
| `GET_EVENT` | `0x0D` | Чтение головной записи общей очереди |
| `ACK_EVENT` | `0x0E` | Подтверждение сохранённой записи |

## Особенности обработки ответов

### Общее правило

- Сервер отправляет команду и ожидает соответствующий ответ/событие до таймаута.
- Таймаут зависит от команды (например, `GET_DEFROST_GROUP`, `SET_DEFROST_GROUP`, `LOAD_DEFROST_DEFAULTS` — 1000 мс).

### `LOAD_DEFROST_DEFAULTS` (`CONFIGURATION 0x02 / 0x06`)

- Запрос: `DataLen = 0`.
- Ответ: стандартный ACK (`Status=OK`), без payload.
- На контроллере: заводские параметры в RAM + EEPROM; авторежим не трогается.
- Сервер (кнопка на вкладке «Параметры») после успеха обычно перечитывает группы 5 и 6.

### `SEND_STATE` (`REQUEST 0x03 / 0x08`)

- Запрос с `DataLen=1` и `Data[0]=0x01` включает флаг очереди в телеметрии.
- Ответ с типом и кодом `03/08` содержит 61 байт данных. Сервер принимает и 60-байтовый вариант прежних прошивок.
- Сервер подтверждает телеметрию отдельной командой `DATA_OK` или `DATA_FALSE`. Лог регулирования после `DATA_OK` приходит только в авторежиме.

### `GET_CMD_INFO`

- `GET_CMD_INFO` в текущей системе запускается **только вручную** кнопкой `button_CMDINFO` в `DataForm`.
- Автоматический запуск `GET_CMD_INFO` по таймаутам/ошибкам отключен.

## Форматы полезной нагрузки (payload)

### `GET_ALARM_FLAGS`

- Запрос: `DataLen = 0`.
- Ответ: `DataLen = 4`.
  - `data[0..1]` -> `Device_AlarmFlags` (`uint16`, little-endian)
  - `data[2..3]` -> `Sensor_AlarmFlags` (`uint16`, little-endian)

### `GET_DEFROST_GROUP`, `groupId=6`

В `DefrostLogGlobalPayload_t` добавлены:

- `debugDisableTargetTStop` (`uint8`)
- `debugDisableDeviceSwitchCheck` (`uint8`)

Порядок полей в конце структуры:

`fishColdTarget_C` -> `debugDisableTargetTStop` -> `debugDisableDeviceSwitchCheck` -> `sensorUseInDefrost[]`

Семантика:

- `debugDisableTargetTStop`:
  - `0` — автостоп по `fishColdTarget_C` включен
  - `1` — автостоп отключен (отладка)
- `debugDisableDeviceSwitchCheck`:
  - `0` — проверка соответствия DO->DI включена
  - `1` — проверка отключена (отладка)

## Имена битов телеметрии (синхронизировано с контроллером)

Первая группа (DI, `T[SQ-1]`, входы модуля I/O) в `DataForm` должна идти строго как `DI_DFR_REGISTERS_t`:

- `Vent1_Left`, `Vent2_Left`, `Vent1_Right`, `Vent2_Right`
- `Ten1_Left`, `Ten2_Left`, `Ten1_Right`, `Ten2_Right`
- `Vent_Out`, `Air_Open`, `Air_Close`, `Gate_Alarm`
- `Gate_Close`, `Gate_Open`, `But_Start`, `But_Stop`

Вторая группа (DO, `H[SQ-1]`, выходы управления) соответствует `DFR_REGISTERS_t`:

- `_V0`, `_V1`, `_V2`, `_V3`
- `_H0`, `_H1`, `_H2`, `_H3`
- `_Out`, `_Inj`, `_Flp`, `_Opn`, `_Dbl`, `_Cls`, `_Wrk`, `_Alr`

Примечание: для `DO15` используется имя `_Alr` (а не `_Stp`/`Alrm`).

| Код | Статус |
|---|---|
| `0x00` | `OK` |

| `0x04` | `INVALID_LENGTH` |

| `0x06` | `TIMEOUT` |
| `0xFF` | `UNKNOWN_ERROR` |
